1. (12 Points) A program is written to compute the sum of the integers from 1 to 10. The
programmer, well trained in reusability and maintainability, writes the program so that it
computes the sum of the numbers from k to n. However, a team of security specialists
scrutinizes the high-level code. The team certifies that this program properly sets k to 1
and n to 10; therefore, the program is certified as being properly restricted in that it
always operates on precisely the range 1 to 10. List at least two different ways that this
program can be sabotaged so that during execution it computes a different sum, for
example, 3 to 20.
One way a program can be sabotaged is that a hacker can change the variables k and n
into different values. For example, a hacker can change variable k from 1 to 3 and/or
change variable n from 10 to 20. Another way a program can be sabotaged is that a
hacker can change the number of items the array can hold using buffer overflow. For
example, a hacker can change the number of items in an array from 10 to 5 to cause the
array to calculate a different sum and create a buffer overflow of an array.

3. (12 Points) List three controls that could be applied to detect or prevent off-by-one
errors.
1) Penetration testing would work because it is an important method to use when it
comes to preventing faults and errors of a program.
2) Hiding information can also prevent off-by-one errors because this is so that the
program won’t be reading information that won’t be needed and would cause buffer
overflow. It will also prevent malicious behaviors, accidents, and actions.
3) Mutual suspicion can prevent off-by-one errors by checking their inputs for reliability
before entering them and defending against flaws and malicious behaviors.
4. (12 Points) Explain in what circumstances penetrate-and-patch is a useful program
maintenance strategy.
Penetrate-and-patch is a useful program to fix any faults and errors found in a program.
However, penetrate-and-patch can sometimes make things worse by causing newer
faults, more failures, more inconsistencies, and more problems.
5. (12 Points) Explain why genetic diversity is a good principle for secure development. Cite
an example of lack of diversity that has had or can have a negative impact on security.
Generic diversity is a good principle for secure development because people should be
aware that too many vulnerable programs can cause viruses and worms to take over
many programs easily. For example, too many HTTP servers that are the same can
increase a higher risk of flaws, faults, and errors.

7. (12 Points) Open design would seem to favor the attacker, because it certainly opens the
implementation and perhaps also the design for the attacker to study. Justify that open
design overrides this seeming advantage and actually leads to solid security.
Open design can sometimes be an advantage because some people want to show the source
codes and programs in public so that the attackers can study the source codes and
programs to give them a good idea on how to program and hack a system, a skill that
attackers need to maintain a secure system.

can be exploited (i.e., not just that it’s a buffer overflow, but where the problem will
manifest itself).
One of the buffer overflows is that the program cannot initialize a variable of type
‘char*’ with an rvalue of type ‘void *’. It can be exploited by fixing the rvalue to the
correct type that will match the type of the variable. In this case, an rvalue should be
type ‘char*’.
