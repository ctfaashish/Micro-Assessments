2. What is Reliable Data Transfer? List all the functionality and features of RDT 1.0, RDT
2.0, 2.1, 2.2, and RDT 3.0. (15 Points)
Reliable Data transfer is to make an unreliable channel reliable by making sure the segments
or packets will be sent to the destination even if there are losses or errors in transmission.
RDT 1.0:
• Underlying channel perfectly reliable: no bit errors and no loss of packets.
• Packets are sent and received with no errors and no packet loss as the channel is perfectly
reliable.
RDT 2.0:
• Underlying channel may flip bits and hence checksum is added.
• ACKs and NACKs are added to explicitly to tell the sender that Packet was received ok
or corrupted.
RDT 2.1:
• There is a possibility that the ACKs and NACKs could be corrupted, and the sender will
resend the packet generating duplicate packets.
• To remove duplicate packets sequence numbers were added.
RDT 2.2:
• NACKs are removed as ACKs are only sent if the packet that was received was error free.
It’s a NACK free protocol.
• The receiver includes the sequence number of the packet that is being ACKed.

4. Describe the TCP segment fields with the segment structure diagram. (20 Points)
Source Port: It indicates the Source Port Number (Sending Computer's TCP Port)
Destination Port: It indicates the Destination Port Number (Receiving Port)
Sequence Number: This number used for byte level numbering of TCP segments.
Acknowledgement number: 32 Bit number field which indicates the next sequence number
that the sending device is expecting from the other device.
Flags: The flag field contains 6 bits. The ACK bit is used to indicate that the value carried
in the acknowledgement for a segment that has been successfully received. The RST, SYN,
and FIN bits are used for connection setup and teardown. Setting the PSH bit indicates that

Header Length: It is the field which shows the number of 32-bit words in the header.
Window size Values: It indicates the size of the receive window, which specifies the number

Checksum: The checksum field is used for error-checking of the header and data.

Data: This is the payload or data that is transmitted from source to destination.

7. What is TCP fast retransmit? Use an example and describe the working of TCP fast
retransmit. (6 Points)
Fast retransmit is a modification to the congestion avoidance algorithm. When the sender
receives 3rd duplicate ACK, it assumes that the packet is lost and retransmit that packet without
waiting for a retransmission timer to expire. When a TCP receiver receives a segment with a
sequence number that is larger than the next, expected, in-order sequence number, it detects a
gap in the data stream that is, a missing segment. This gap could be the result of lost or
reordered segments within the network. it simply re-acknowledges (that is, generates a
duplicate ACK for) the last in-order byte of data it has received. In the case that three duplicate
ACKs are received, the sender assumes that the segment following the one that has been
acknowledge thrice had been lost. Thus, the TCP sender performs a fast retransmit.

8. Explain in detail how TCP flow control is done? (5 Points)
Suppose the sender wants to send data to the receiver. How much data will the sender send?
TCP offers a service called flow-control, where the sender will make sure not to overflow the
receiver’s buffer. Let us assume sender wants to send a large file. The large file is split into
segments. When the sender establishes connection with the receiver, the receiver creates a
receive buffer. When the segment is sent to the receiver, the receiver sends back an
acknowledgement. This acknowledgment is a TCP segment that contains the rwnd field. The
rwnd field tells the sender about the remaining buffer at the receiver side. With the rwnd value,
the sender can keep track of the data it can potentially send to the receiver. The sender ensures
that the last byte sent minus last byte acknowledged is always less that the remaining size of the
receiver’s buffer (rwnd). The below video discusses about TCP flow control.

9. What are the steps involved in opening and closing a TCP connection? Clearly state what
information is exchanged between the client and the server during the opening and closing a
TCP connection. (10 Points)
Opening a TCP Connection:
When a host wants to connect to a TCP server, first it needs to do a negotiation with the server
using the “Three-way handshake”.
Step 1: The host sends a segment with SYN flag set with a random sequence number x

Step 2: When TCP server receives a "SYN" segment which carries no acknowledgment after
it has sent a "SYN". Server responds by setting "ACK" and "SYN" flags. The server sequence
is a random sequence number y and the acknowledgment number is x + 1
Step 3: Client responds to the received segment by setting "ACK" flag and by appending the
available data to the segment. The sequence number is x + 1 and the acknowledgment number
is y + 1.
Closing TCP connection:
TCP Connection termination is achieved as shown below.
Step 1: When the host wants to terminate the connection, it sends a segment with FIN flag set
to 1. The sequence number is set of x
Step 2: The server responds back with an ACK with an acknowledgment number x + 1
Step 3: When the server does not have any data for transmission, it sends again a segment
with FIN flag set to 1 and sequence number y
Step 4: The host responds back with an ACK, and the server-side connection is terminated.
The acknowledgment number is y + 1. The client will wait for 2*max segment lifetime and
closes the connection on the client side.
