5. What are the minimal permissions which are necessary for an ordinary (unprivileged) user to delete
a file /d1/f ? This means that the root directory contains a subdirectory “d1”, which contains the file
named “f”. Assume that the user has “rwx” (i.e., read, write, execute) permissions for the root
directory, and that the permissions for the root directory do not need to be minimized. Usually all
you need is the write permission and search permission to delete a file so “rw-“ is enough but,
“changing the name of a file or deleting it completely are not tasks that require the write() system
call. So a user doesn't need read (r) or write (w) permission to rename or delete a file.” You only
need write permission on the directory that contains the file.
Note: Clearly, if the user has “rwx” permissions for both “d1” and “f” then it is possible to delete “f”.
How about when the user has “rw-” (i.e., read, write, but no execute) permission for “f”?
Or “rw-” permission for “d1”, etc.
Tip: This document contains a useful explanation:
https://wpollock.com/AUnix1/FilePermissions.htm
