Background
In this lab, we will be using Docker technology, which is one of the most popular container technologies
today. Below, you will find some information on how it works and some terminology.
Terminology
• Images - The blueprints of applications which form the basis of containers. We will use different
images in this lab. This is similar to the iso images we download.
• Containers - Created from Docker images and run the actual application. This is similar to the
VM we create using the iso images.
• Docker Daemon – This is the background service to manage building, running and distributing
Docker containers. The daemon is the process that runs in the operating system which clients talk
to.
• Docker Client - The command line tool that allows the user to interact with the daemon. Even
though there exists GUI based tools, we will use command line client in this lab.
• Docker Hub - A registry (collection) of Docker images publicly available but you can also create
your own Docker registry. You can think of the registry as a directory of all available Docker
images. If required, one can host their own Docker registries and can use them for pulling images.
How does it work?
When we have the Docker images, they are a stack of read-only application layers and when we create a
container, Docker engine uses this read-only stack of layers and adds an additional read+write stack on
top. This allows us to have the required software layers and on top the user data in a way that these user
data (in read+write layer) will not affect the original files in the read-only layer; i.e., Docker image. This
also means that when we create and modify things on the read+write layer, when we remove the
container, these data will no longer exist.
Where do we store the files then? Considering VirtualBox VMs as an example, we create and have the
files under “~/VirtualBox VMs” as .vbox files for the definition of the VMs and .vdi files for the virtual
harddrives. Also, we have a directory for the Snapshots. Similarly, for Dockers, we have the Volumes to
store data as part of the host file system (“/var/lib/docker/volume”) managed by Docker.
