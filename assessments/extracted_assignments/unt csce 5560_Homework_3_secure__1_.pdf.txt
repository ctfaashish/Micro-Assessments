B) Countermeasures for
XSS:
1. Escaping: The first and most important approach for avoiding XSS vulnerabilities in
your applications is to escape user feedback. When an application receives data, it
must first ensure that it is safe before rendering it to the end user. By escaping user
feedback, malicious interpretation of key characters indata obtainedby awebpage is
avoided.
2. Validating: Validating input ensures that an application renders the correctdata while
also preventing malicious data from causing harm to the web, database, and users.
While whitelisting and input validation are more commonly associated with SQL
injection, they can also be used to protect against XSS.
3. Sanitizing: Sanitizing user feedback is a third way to avoid cross-site scripting
attacks. Data sanitization is an effective defense, but it should not be used alone to
combat XSS attacks. It's entirely conceivable that you'll need to employ all three
mitigation strategies in order to construct a more reliable application.
SQL Injection:
1. Firewall: To help filter out malicious data, consider using a web application firewall
(WAF) – either software or an appliance. The best ones will come with a
comprehensive collection of default rules and make it simple to add new ones as
needed. A WAF can be especially useful for providing security protection against a
new vulnerability before a patch is issued.
2. Reduce your attack surface: Remove any database features that you don't need to
avoid a hacker exploiting it. The xp cmdshell extended stored procedurein MSSQL,
for example, launches a Windows command shell and accepts a string for execution,
which could be extremely useful to a hacker.
3. Update and Patch: Hackers can exploit SQL injection vulnerabilities in applications
and databasesonaregular basis,soit'simportant toimplement patchesand updatesas
soon as possible.

result, the only way to deal with buffer overflow issues is to avoid them in the first
place.

Hashing is the process of mapping data of anysizetoafixedlength using analgorithm. This
is known as a hash value (or hash code, hash sums, or even a hash digest if you want to get
fancy).
The role of hashing isone-way.Although itis theoreticallypossible toreverse-hashanything,
the necessary computing power makes it impractical.
Hashing is one-way.
The wayit worksisthat eachhashing algorithm producesafixed-lengthoutput. Forexample,
SHA-256 denotes that the algorithm will generate a hash value of 256 bits, which is usually
represented by a 64-character hexadecimal string (h/t Matthew Haslett).
Now, while encryption protects data in transit, hashing verifies that a file or piece of data
hasn't been tampered with—that it's real. To put it another way, it works as a checksum.
Every hash value is one-of-a-kind. A collision occurs when two separate files contain the
same unique hash value, rendering the algorithm effectively useless.

a) The Public Key Infrastructure (PKI) is a collection of applications, encryption
technologies, and services that enable organizations to secure their network communications
and business transactions. PKI allows a range of other security services, such as data
confidentiality, data integrity, and non-repudiation, by integrating private (e.g., secret) key
and public key cryptography. PKI is a network security architecture that combines digital
certificates, public key cryptography, and certification authorities into a single system.
A PKI certificate enables anyone to digitally bind their identity and perform any of the
following functions:
● It encrypts and authenticate documents and email messages.
● It performs digitally sign email and documents.
● Users' authentication and/or authorization to networks and applications, for example,
PIV credential login
● A user's permission to use an application gives them the opportunity to perform
unique tasks.

Trust models:
Trust models provide a framework for establishing and managing trust between the various
components of a public key infrastructure (PKI). The certification path validation process,
which includes path discovery, signature verification, and revocation status testing, verifies
these trust relationships.
There are 4 types that are used to implement the trust model with PKI:
● Hierarchical Trust Model
● Bridge Trust Model
● Hybrid Trust Model
● Mesh Trust Model
Certificate Authority:
The CA is in responsible for all aspects of certificate administration for a PKI, including
certificate lifecycle management phases. A certificate issued by a CA is used to verify that
the subject onthecertificate isthe ownerof thepublic key.Theclientcreatesapublic-private
key pair in a PKI scheme. The CA receives the public key andthe detailstobe imprintedon
the certificate.
Root Certificates and the Certificate Chain:
When a CA issues a PKI certificate, it begins by validating the individual to which it is
issuing. After that, it generates a certificate containing the validateddata andsigns it withits
private key.
Any PKI certificate that has been signed by a trusted root can be trusted. CAs, on the other
hand, almost never sign directly from their trusted origins. It's too dangerous and could lead
to technical difficulties. Instead, CAs create intermediate roots that they sign with their
confidence roots. End user or leaf certificates are then issued using certain intermediate roots.
Authenticating PKI certification:
Handshakes are used in PKI infrastructure for authentication (and, in the case of SSL/TLS,
for negotiating encryption parameters). When PKI isused, theserver or enduserpresents the
other party with its certificate and public key at the start of the link or session.
